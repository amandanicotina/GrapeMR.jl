## How to contribute to GrapeMR

#### **Did you find a bug?**

* **Ensure the bug was not already reported** by searching on GitHub under [Issues](https://github.com/amandanicotina/GrapeMR.jl/issues).

* If you're unable to find an open issue addressing the problem, [open a new one](https://github.com/amandanicotina/GrapeMR.jl/issues/new). Be sure to include a **title and clear description**, as much relevant information as possible, and a **code sample** or an **executable test case** demonstrating the expected behavior that is not occurring.

#### **Did you write a patch that fixes a bug?**

* Open a new GitHub pull request with the patch.

* Ensure the PR description clearly describes the problem and solution. Include the relevant issue number - please ensure to open an issue prior to opening your PR.

#### **Did you fix whitespace, format code, or make a purely cosmetic patch?**

Changes that are cosmetic in nature and do not add anything substantial to the stability, functionality, or testability of GrapeMR will generally not be accepted (we follow Ruby on Rail's [rationales behind this decision](https://github.com/rails/rails/pull/13771#issuecomment-32746700)).

#### **Do you intend to add a new feature or change an existing one?**

* Suggest your change in an issue using the feature request template.

* Do not open a PR on GitHub until you have collected positive feedback about the change.

#### **Do you have questions about the source code?**

* Ask any question about how to use GrapeMR in the form of an issue. Be sure to include a **title and clear description**, as much relevant information as possible, and a **code sample** with annotations inline in the form of comments, or below code samples in prose.

GrapeMR is mostly an individual effort, stemming from [@amandanicotina](https://github.com/amandanicotina)'s research during her PhD.
As there's no team behind it, please be patient with any communication, a response might not be immediate.

Thanks for considering to contribute! :heart:
